# Spec 07 — CMS 管理后台

## 1. 目标
官网需要一个简单、稳定、低学习成本的内容管理后台，视觉和操作理念可参考 LabID 现有主页管理后台，突出“所见即所得”或至少“编辑后即时预览”。

CMS 是官网维护工具，不是 LabID 客户端产品后台。

## 2. 角色
V1 可只有一种管理员角色：
- Admin

不需要复杂 RBAC。

## 3. 登录
必须有后台登录保护。
建议：
- `/admin`
- 账号 + 密码或成熟身份认证方案；
- Session 安全；
- 生产环境禁止默认密码；
- 登录失败 rate limit。

## 4. 首页内容管理
至少提供以下模块：

### A. Hero
- Eyebrow
- 主标题
- 描述
- Primary CTA
- Secondary CTA
- Hero 图片/媒体

### B. Product
- 区块标题
- 描述
- 三个核心价值项
- 每项图标/图片

### C. Cases
- 列表管理
- 新增、编辑、删除
- 排序
- 上下线
- 封面上传
- URL

### D. Contact
- 标题
- 描述
- 电话
- 邮箱
- 响应时效提示
- 成功提示

### E. Footer
- 备案号
- 公司版权名称
- 年份显示规则

## 5. 编辑体验
优先实现：
- 左侧/右侧编辑；
- 即时预览；
- 或编辑页面中嵌入实时 Preview。

最低要求：
- 修改字段后可以预览；
- 保存后官网立即或在明确刷新机制后更新；
- 不需要开发者重新部署。

## 6. 发布模型
V1 可选两种之一：

### 方案 A：直接保存即发布
适合团队很小，开发成本最低。

### 方案 B：Draft + Publish
更安全：
- 草稿；
- 预览；
- 发布。

若实现成本可控，优先 B。

## 7. 图片管理
- 上传图片；
- 替换；
- 删除；
- 自动生成适合 Web 的尺寸；
- 限制文件类型和大小；
- 保存 alt text；
- 不使用本地临时文件路径作为线上地址。

## 8. 防止误操作
- 删除案例二次确认；
- 离开未保存页面提示；
- URL 字段基本校验；
- 必填文案为空时阻止发布；
- 保留合理默认内容。

## 9. 内容版本
V1 不强制完整版本历史。
但建议至少保存：
- updated_at
- updated_by

如实现 Draft/Publish，可保留最近一次已发布版本以便回滚。

## 10. Leads 管理
V1 CMS 建议增加简易“咨询线索”列表：
- 提交时间；
- 学校；
- 院系；
- 姓名；
- 联系方式；
- 留言摘要；
- 状态：新线索 / 已联系 / 已关闭。
- 邮件、短信及后续扩展渠道的独立投递状态、目标、尝试次数和最后错误；

支持查看详情、修改状态，并对失败渠道单独重试，不重复发送已经成功的其他渠道。
不需要复杂销售漏斗。

## 11. 审计与安全
- 后台不可被搜索引擎索引；
- 不在前端包中暴露管理员凭证；
- 所有写操作服务端鉴权；
- 上传接口限制 MIME / extension / size；
- 基础操作日志。

## 12. 验收标准
- 管理员无需改代码即可维护首页核心内容；
- 可管理三个案例并新增案例；
- 可修改 Contact 信息；
- 可查看提交的销售线索；
- 未登录用户无法进入后台；
- 保存/发布后官网内容同步更新。
