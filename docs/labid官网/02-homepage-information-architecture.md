# Spec 02 — 首页信息架构与页面流

## 1. 页面模型
V1 仅包含一个公开页面 `/`，采用纵向单页结构。

页面自上而下：
1. Header / 顶部导航
2. Hero / 头图
3. Product / 产品说明
4. Cases / 虚拟案例
5. Contact / 联系我们
6. Footer / 页脚

## 2. Header
### 必须元素
- LabID Logo
- 导航：产品、案例、联系我们
- 主 CTA：联系我们

### 行为
- 导航点击后平滑滚动到对应 section；
- 当前无需进入二级页面；
- Header 可采用透明 → 滚动后浅色背景的方式，但必须保持克制；
- 移动端折叠为菜单；
- Logo 点击回到页面顶部。

## 3. Section ID
建议固定：
- `#product`
- `#cases`
- `#contact`

CMS 修改文案时不得改变锚点。

## 4. 页面阅读路径
### 首屏
回答：
- LabID 是什么？
- 为谁服务？
- 为什么它与普通建站不同？

### 第二屏：产品
回答：
- 为什么准备材料更轻？
- AI 具体扮演什么角色？
- 为什么页面后续容易持续维护？

### 第三屏：案例
回答：
- 最终做出来是什么样？
- 不同学科、不同团队规模能否适配？

### 第四屏：联系
回答：
- 如何开始？
- 需要提供哪些基本信息？
- 多久会得到回应？

## 5. 桌面端布局
建议最大内容宽度 1200–1440px。
- 文本内容避免占满全屏；
- 每一大 section 保持明显上下留白；
- 案例区允许更宽的视觉区域；
- 首页一级模块统一采用“标题先行、内容后置”的垂直阅读顺序；
- Eyebrow、标题、导语和主要操作必须先于图片、卡片、表单或详细说明出现，并占据独立的完整内容行；
- 禁止标题在左、视觉或内容在右的左右分列 Hero 或 Section Heading；
- Hero 允许把完整的垂直标题组、说明和 CTA 叠放在沉浸式背景图上，但不得拆成左右两栏；
- 仅标题之后的案例集合、价值详情、联系信息和表单字段等内容主体允许分列；
- Contact 标题与导语必须位于完整宽度的上方，表单在标题组之后继续采用完整宽度的垂直布局，不与标题或支持信息左右并列。

## 6. 移动端布局
- 所有双栏自动转单栏；
- CTA 保持清晰；
- 案例卡片纵向排列；
- 表单输入控件宽度 100%；
- 不出现横向滚动；
- 导航收起，不遮挡页面主要内容。

## 7. 锚点与 URL
允许 URL hash：
- `/#product`
- `/#cases`
- `/#contact`

刷新后仍应定位到目标 section。

## 8. 基础状态
必须定义：
- 首屏资源加载中；
- 案例缩略图加载失败；
- 表单提交中；
- 表单提交成功；
- 表单提交失败；
- CMS 内容为空时的 fallback。

## 9. 验收标准
- 页面结构严格遵循 6 个一级区域；
- 导航均正确定位；
- V1 不出现无法完成的二级页面入口；
- 移动端可完整浏览和提交表单；
- 页面阅读顺序清晰，无重复功能模块；
- 任何视口下，一级模块标题都先于该模块的内容主体出现。
