# Spec 03 — 视觉设计系统

## 1. 视觉方向
整体参考 OpenAI 与 Google DeepMind 官网的视觉语言：
- 现代；
- 克制；
- 高信息品质；
- 大留白；
- 精细排版；
- 强调内容而不是装饰；
- 卡片有层级，但不过度拟物。

不要求像素级复制任何参考网站。

## 2. 色彩
### 主背景
以白色、暖白或非常浅的中性色为主。

### 文字
- 主文字：接近黑色；
- 次级文字：中性灰；
- 弱辅助信息：更浅灰。

### 品牌色
允许使用 LabID 品牌色作为：
- CTA；
- hover；
- 标签；
- 小范围强调。

禁止大面积高饱和品牌色铺底，除非后续品牌规范另有规定。

## 3. 字体
优先系统可稳定加载的无衬线字体栈。
中英文都要保证清晰和现代。

建议：
- 中文：PingFang SC / Microsoft YaHei / Noto Sans SC fallback；
- 英文：Inter / system-ui fallback。

### 字号建议
- Hero H1：桌面 56–72px；移动 38–48px；
- Section H2：桌面 36–48px；移动 30–36px；
- Body：16–20px；
- Caption：13–14px。

首页关键正文采用固定层级：产品、案例和联系区导语 18px；产品价值说明与联系表单文字 16px。

实际实现应使用 clamp() 做流式响应。

## 4. 间距
建立 4/8px 基础 spacing scale。
大 section 建议上下间距：
- Desktop：120–180px；
- Mobile：72–104px。

文字最大行宽建议 620–760px。

### 4.1 一级模块版式规则
- 首页一级模块采用垂直阅读顺序；
- Eyebrow、一级/二级标题、导语和主要操作必须先于该模块的图片、卡片、表单或详细说明出现；
- 标题组必须占据独立的完整内容行，不得与视觉或内容主体左右并列；
- Hero 可将完整标题组垂直叠放在沉浸式背景图上；除 Hero 背景层外，媒体位于对应标题组之后；
- 案例卡、价值详情、数据、联系信息和表单字段可在标题之后使用网格或分栏；
- 产品、案例与联系区的主标题在宽屏不得人工断行或添加句末句号；相关单句导语在宽屏优先保持单行，空间不足时允许自然换行，且不得因此产生横向滚动；
- Contact 表单整体在标题组下方占据完整内容宽度；表单内部字段仍可分列；
- Header 导航与 Footer 工具信息不受此内容版式规则限制。

## 5. 圆角与边框
- 卡片圆角：16–28px；
- 按钮圆角：可采用胶囊或 10–14px，需全站统一；
- 边框使用低对比中性色；
- 阴影尽量轻，优先用边框和背景层级建立关系。

## 6. 案例卡片
案例卡片是首页最重要的视觉组件之一。
必须包含：
- 学科；
- 团队规模；
- 预览视觉；
- 明确“查看案例”行为。

Hover：
- 图片轻微缩放或卡片位移；
- 动效时长约 180–300ms；
- 不使用夸张 3D 翻转。

## 7. 动效
仅使用辅助理解的微动效：
- 页面元素轻微淡入；
- 卡片 hover；
- 导航状态；
- CTA hover；
- Hero 媒体轻微变化。

支持 `prefers-reduced-motion`。

## 8. 图片
若正式素材尚未准备：
- 允许开发阶段生成占位图片；
- 占位图片必须集中管理，后续可在 CMS 中替换；
- 禁止将临时素材写死在组件内部。

## 9. 响应式断点
建议：
- Mobile: < 768px
- Tablet: 768–1023px
- Desktop: >= 1024px
- Wide: >= 1440px

不要仅依赖固定断点；文本、间距与 grid 应结合 fluid layout。

## 10. 无障碍
- 正文与背景保持足够对比；
- focus 状态可见；
- 所有可点击卡片支持键盘操作；
- 图片有 alt；
- 表单 label 不得仅使用 placeholder 替代。

## 11. 验收标准
- 视觉整体为浅色、克制、高留白；
- 不出现模板化 AI 渐变视觉；
- 中英文排版均无断裂；
- 动效不过度；
- Hero、产品、案例和联系区均遵循“标题 → 内容主体”的垂直顺序；
- 360px 宽移动设备到宽屏桌面均无明显视觉问题。
