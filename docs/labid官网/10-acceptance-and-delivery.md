# Spec 10 — 开发、验收与交付

## 1. 目标
给出 Codex 完成 LabID 官网 V1 的统一 Definition of Done。

## 2. 推荐开发阶段

### Phase 1 — Skeleton
- 初始化项目；
- 建立全局样式和设计 token；
- 首页六大 section；
- 响应式布局；
- 用 seed 内容跑通。

### Phase 2 — Visual
- 完成 Hero；
- 产品区；
- 三个案例；
- Contact；
- Footer；
- 微动效。

### Phase 3 — Backend
- 数据库；
- 内容 API；
- Lead API；
- 邮件通知；
- 图片存储。

### Phase 4 — CMS
- 登录；
- 首页内容编辑；
- 案例 CRUD；
- 联系信息编辑；
- Lead 列表。

### Phase 5 — Hardening
- SEO；
- 性能；
- 安全；
- 错误状态；
- Analytics；
- 部署。

## 3. 必须通过的功能验收

### Public Website
- [ ] `/` 正常访问
- [ ] Header 导航定位准确
- [ ] Hero 清楚传达 LabID 定位
- [ ] 产品区明确 AI 自动梳理能力
- [ ] 产品区明确所见即所得持续编辑能力
- [ ] 三个案例内容和 URL 全部准确
- [ ] Contact 显示 48 小时内联系
- [ ] Footer 显示备案号与公司版权

### Lead Form
- [ ] 学校必填
- [ ] 院系必填
- [ ] 姓名必填
- [ ] 联系方式必填
- [ ] 留言必填
- [ ] 服务端校验
- [ ] 成功提交后落库
- [ ] 成功提交后通知 `276238375@qq.com`
- [ ] 提交成功状态明确
- [ ] 提交失败不丢失用户输入
- [ ] 有基础防垃圾提交机制

### CMS
- [ ] 管理员登录
- [ ] 修改 Hero
- [ ] 修改产品说明
- [ ] 管理案例
- [ ] 替换案例封面
- [ ] 修改 Contact 信息
- [ ] 修改 Footer
- [ ] 查看 Leads
- [ ] 修改 Lead 状态
- [ ] 未授权用户无法写入

## 4. 视觉验收
- [ ] 视觉为浅色主基调
- [ ] 具备 OpenAI / DeepMind 风格中的克制、留白、排版品质
- [ ] 不使用模板化 AI 大渐变
- [ ] 案例是主要视觉重点
- [ ] 360px 移动端无横向滚动
- [ ] 768px 平板布局正常
- [ ] 1440px 桌面布局不过度拉伸
- [ ] Hero、产品、案例和联系区的标题均未与内容主体左右并列
- [ ] DOM 顺序与视觉阅读顺序一致
- [ ] 1440px、1024px、768px、390px 下标题始终先于模块主体
- [ ] 新增模块默认采用垂直标题结构，分列仅用于标题后的内容主体
- [ ] 宽屏下产品、案例和联系区主标题及单句导语优先单行展示，窄屏可自然换行且无横向滚动
- [ ] Hero CTA 位于头图内容区底部，且不存在独立“服务对象”辅助行
- [ ] Contact 表单整体位于标题组下方并占据完整宽度，提交按钮位于表单右下角
- [ ] hover/focus 状态完整
- [ ] reduced motion 有降级

## 5. 内容验收
- [ ] 目标用户统一为 PI / 研究团队负责人
- [ ] 不出现博士生作为核心用户的表达
- [ ] 不出现“免费试用/内测”
- [ ] 不自行编造客户、合作高校、价格、交付时长
- [ ] 案例明确标记为不同学科与团队规模
- [ ] 文案没有把 LabID 表述成普通模板建站工具

## 6. 技术验收
- [ ] secrets 使用环境变量
- [ ] `.env.example` 不含真实密钥
- [ ] 数据库 migration 可复现
- [ ] 提供 seed 数据
- [ ] 项目可在全新环境启动
- [ ] README 包含本地运行和部署说明
- [ ] 构建无错误
- [ ] 关键页面无 console error
- [ ] 404/500 有合理处理
- [ ] 管理后台 noindex

## 7. 测试
至少包含：
- Lead 表单校验测试；
- Lead API 成功/失败测试；
- CMS 权限测试；
- Case 数据读取测试；
- 核心页面 smoke test。

如果技术栈支持 E2E，建议覆盖：
`打开首页 → 查看案例 → 回到官网 → 填写表单 → 提交成功`。

## 8. 交付物
Codex 最终应交付：
- 完整源代码；
- 数据库 schema + migration；
- seed；
- `.env.example`；
- 项目 README；
- CMS 管理说明；
- 部署说明；
- 测试；
- 最终页面截图或录屏；
- 未完成项清单（如果存在）。

## 9. 最终 Definition of Done
只有在以下条件同时满足时才算 V1 完成：
1. 首页视觉达到可正式对外发布水平；
2. 三个 demo 案例可点击；
3. 表单线索不会丢失；
4. 指定邮箱能收到通知；
5. CMS 可在不改代码情况下维护核心内容；
6. 移动端可用；
7. 无明显安全与 SEO 基础缺陷；
8. 页面中不存在与产品定位冲突的临时文案。
