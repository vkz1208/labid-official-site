# Spec 04 — Hero 与产品叙事

## 1. 目标
Hero 与产品说明区域需要在最短阅读路径内建立 LabID 的差异化认知。

核心信息必须包含：
- LabID 服务于高校 PI 与研究团队；
- 产品是 AI 时代的学术数字身份服务；
- 当前核心产品是专属学术主页；
- AI 可自动识别科研工作并梳理研究脉络与科研叙事；
- 后续可通过所见即所得后台持续更新。

## 2. Hero 结构
建议包含：
- Eyebrow：AI-native Academic Identity / 类似短标签；
- H1：一句核心品牌主张；
- 1–2 句说明；
- Primary CTA：查看案例；
- Secondary CTA：联系我们；
- 背景视觉：无烘焙文字的沉浸式科研场景。

Hero 使用整幅图片作为首屏背景，内容按“Eyebrow → H1 → 说明 → CTA”垂直叠放在图片上。桌面端也不得将标题与媒体拆成左右两栏，不展示编辑刊号、日期或独立的“服务对象”辅助行。目标用户信息应由首屏说明自然表达。Slogan 使用白色，说明与辅助文字使用降级白色，按钮必须在背景上保持清晰对比；宽屏下 Slogan 与说明之间保留约 120px 的明显留白，平板和手机按可用高度收紧；CTA 组固定在头图内容区底部。

### Hero 禁止
- 大段功能列表；
- 标题在左、媒体在右的分列首屏；
- 把 Slogan、说明和 CTA 烘焙进图片文件；
- 在图片上叠加无实际作用的研究数据或装饰性文字；
- 虚假的客户数字；
- 未经确认的高校 Logo 墙；
- “免费开始”“立即试用”。

## 3. 产品说明区
建议拆成三个关键价值块，而不是十几个小功能点。

### Value 1 — AI 自动完成前期梳理
表达重点：
用户无需繁琐准备大量材料。
AI 可围绕公开科研工作识别和整理相关信息。

### Value 2 — 从成果列表变成科研叙事
表达重点：
不只是把论文堆在页面上，而是围绕研究方向、成果关系与研究脉络进行组织。

### Value 3 — 所见即所得，持续维护
表达重点：
主页交付后不是一次性静态页面。
用户可通过可视化后台持续更新内容，并即时看到页面效果。

## 4. AI Native 表达
可以强调 LabID 从产品设计开始即基于 AI，而非传统网站模板叠加 AI。
但不得在未实现的能力上过度宣传。

推荐表达逻辑：
“AI 负责理解与组织科研信息，人负责最终判断和呈现。”

## 5. 内容可配置
CMS 至少支持：
- Hero eyebrow；
- H1；
- Hero description；
- CTA 文案与链接；
- Hero media；
- 产品区标题；
- 产品区说明；
- 三个 value block 的标题、说明、图标/视觉。

## 6. 视觉表现
- Hero 不宜塞满屏幕；
- 首屏应保留明显留白；
- Hero 图片文件本身不包含文字并横向铺满；真实 Slogan、说明和 CTA 以可访问的 HTML 叠放在背景上；
- 产品区标题和说明占据完整内容行，三个价值块只能在标题之后分列；
- Hero、产品区、案例区和联系区主标题不使用句末句号；产品区与案例区标题不写入人工换行，宽屏标题及单句导语优先保持单行，空间不足时允许自然换行；
- 产品界面视觉应真实体现 LabID 页面，而不是抽象 AI 球体；
- 产品说明卡片在视觉上可各自独立，但保持统一布局语言。

## 7. 验收标准
- 首屏出现目标用户与核心价值；
- 明确出现 AI 自动梳理 + 所见即所得后台两类差异化能力；
- CTA 可以进入案例与联系区；
- 所有主要文案均可 CMS 更新；
- 无“免费试用”等错误商业表达。
