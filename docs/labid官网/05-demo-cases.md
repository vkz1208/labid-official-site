# Spec 05 — 虚拟案例模块

## 1. 目标
案例是首页最重要的信任建立模块。用户需要通过案例直接理解 LabID 的最终交付形态，而不是只阅读抽象产品描述。

## 2. 固定首批案例
### Case A
- 标签：生命科学
- 团队规模：大型研究团队
- URL：https://demo-life.labid.cn/

### Case B
- 标签：化学
- 团队规模：中型课题组
- URL：https://demo-chem.labid.cn/

### Case C
- 标签：材料学
- 团队规模：小型课题组
- URL：https://demo-materials.labid.cn/

## 3. 展示方式
桌面端建议三张大卡片或 1+2 非对称网格。
案例区主标题不使用句末句号；标题与单句导语在宽屏保持单行，在较窄视口自然换行。
每张案例卡至少显示：
- 学科；
- 团队规模；
- 页面截图/预览图；
- “查看案例”；
- 外链标识（可选）。

不需要在卡片上编造 PI 姓名、学校或科研成果。

## 4. 点击行为
- 点击卡片或“查看案例”打开对应 demo；
- 建议新标签页打开；
- 加 `rel="noopener noreferrer"`；
- 卡片整体为可点击区域；
- 同时保证键盘可访问。

## 5. CMS
后台需要支持：
- 新增案例；
- 删除案例；
- 编辑案例；
- 拖拽排序或设置排序值；
- 开启/关闭显示；
- 学科；
- 团队规模；
- 封面图；
- URL；
- 可选短说明。

V1 默认预置三个案例。

## 6. 图片策略
- 案例封面优先使用对应 demo 页面截图；
- 如果开发时没有正式截图，可先生成占位图；
- 上线前建议替换为真实 demo 截图；
- 图片需压缩为 WebP/AVIF 等现代格式；
- 需设置固定 aspect ratio，避免页面跳动。

## 7. 外链异常
如果某案例 URL 暂时不可用：
- 官网卡片仍可显示；
- 点击时不应导致主站崩溃；
- 可由 CMS 临时关闭链接或整个案例。

## 8. 可扩展性
未来可能出现更多学科和规模，因此组件不得硬编码只能展示三个。
建议支持 1–12 个案例。

## 9. 验收标准
- 三个指定案例全部准确展示；
- URL 无误；
- 卡片视觉质量高于普通功能列表；
- CMS 可调整内容与顺序；
- 新增第 4 个案例无需修改前端代码。
